# 第五轮迭代任务拆解清单

## 1. 迭代目标

本轮任务以“收口、对齐、稳定化、可验收”为核心，不以新增大功能为目标，重点解决当前代码实现中已经暴露的问题，打通 MVP 主链路并补齐上线前必要能力。

---

## 2. 任务总览

| 编号 | 任务名称 | 优先级 | 负责方向 | 依赖 |
|------|----------|--------|----------|------|
| T5-01 | 数据结构对齐与初始化补全 | P0 | backend | 无 |
| T5-02 | API 契约收口与文档统一 | P0 | architect / docs | T5-01 并行可做 |
| T5-03 | 主链路联调与验收清单建立 | P0 | frontend / backend / test | T5-01、T5-02 |
| T5-04 | 错误结构统一 | P1 | backend | T5-02 |
| T5-05 | Pipeline 持久化改造 | P1 | backend | T5-01 |
| T5-06 | 环境配置校验与错误提示优化 | P1 | backend / frontend | T5-04 |
| T5-07 | API 集成测试补齐 | P2 | test | T5-03、T5-04 |
| T5-08 | E2E 主链路测试补齐 | P2 | test | T5-03 |
| T5-09 | 页面空态与异常态统一 | P2 | frontend | T5-03、T5-06 |

## 3. 任务拆解

### T5-01 数据结构对齐与初始化补全

**目标**

- 修复 `data/db.json` 与 `src/lib/db.ts`、`src/lib/types.ts` 的结构不一致问题
- 确保首页、设置页、账号空间、报告页在空数据或默认数据下可正常工作

**子任务**

1. 检查 `db.json` 当前根字段是否完整
2. 对齐 `Database` 类型定义
3. 为缺失字段补空数组或默认值
4. 补充至少 1 条分类数据
5. 为后端读取逻辑增加缺字段兼容
6. 验证分类页、设置页、账号空间页、报告页是否能正常加载

**交付物**

- 对齐后的 `data/db.json`
- 补强后的 `src/lib/db.ts`
- 数据结构对齐说明

**验收标准**

- 首页能正常显示分类
- 缺少某个数组字段时不报 500
- 页面能处理空态数据

---

### T5-02 API 契约收口与文档统一

**目标**

- 让 `docs/api-contract.md` 与现有代码实现一致
- 删除重复章节和冲突描述

**子任务**

1. 梳理当前实际存在的 API 路由
2. 清理重复的“AI 内容生成”章节
3. 明确 `content/generate` 与 `content/write` 的职责边界
4. 明确 `content/cover` 与 `content/cover/prompts` 的职责边界
5. 对齐平台搜索接口名称
6. 补充 Wiki、报告、账号空间、Pipeline 的契约缺口
7. 统一成功/失败响应示例

**交付物**

- 收口后的 `docs/api-contract.md`
- 接口差异清单

**验收标准**

- 文档无重复接口章节
- 文档能直接指导前后端联调
- 路由路径、请求方式、响应字段与代码一致

---

### T5-03 主链路联调与验收清单建立

**目标**

- 建立项目当前版本的统一验收链路
- 明确“已完成”和“不可交付”的边界

**主链路**

1. 创建分类
2. 创建关键词
3. 触发内容采集
4. 查看文章列表
5. 提取文章到 Wiki
6. 查看 Wiki 索引和日志
7. 执行 Wiki 健康检查
8. 生成选题报告
9. 基于 Wiki 生成正文
10. 生成标题和封面 Prompt

**子任务**

1. 为每个步骤补参数说明
2. 为每个步骤定义成功标志
3. 为每个步骤定义失败提示
4. 检查页面状态与接口数据是否一致
5. 产出统一验收清单

**交付物**

- 主链路验收 checklist
- 联调问题记录

**验收标准**

- 主链路 10 步都可执行
- 每一步有明确成功/失败标准

---

### T5-04 错误结构统一

**目标**

- 收敛 API 错误返回结构，方便前端统一处理

**子任务**

1. 统计当前使用 `msg` 和 `error` 的接口
2. 定义统一错误结构
3. 修改路由错误返回格式
4. 同步更新前端错误处理逻辑
5. 更新接口文档错误示例

**建议格式**

```json
{
  "code": 400,
  "error": {
    "name": "BAD_REQUEST",
    "message": "缺少必要参数"
  }
}
```

**交付物**

- 统一后的 API 错误结构
- 前端错误处理收口说明

**验收标准**

- 同类错误在不同接口结构一致
- 前端能复用统一错误展示逻辑

---

### T5-05 Pipeline 持久化改造

**目标**

- 将内存态管道执行状态改为可恢复、可审计的数据结构

**子任务**

1. 设计 pipeline 存储结构
2. 将任务状态写入 `db.json` 或专用存储
3. 支持按任务 ID 查询执行状态
4. 增加任务开始时间、更新时间、失败原因
5. 验证服务重启后的任务恢复能力

**交付物**

- 持久化后的 pipeline 数据结构
- 改造后的管道状态查询接口

**验收标准**

- 管道记录可跨重启保留
- 失败步骤可追踪
- 查询接口返回完整执行历史

---

### T5-06 环境配置校验与错误提示优化

**目标**

- 让用户在缺少配置时能明确知道问题与处理路径

**子任务**

1. 梳理 AI 与平台采集依赖的环境项
2. 增加运行前校验
3. 优化 API 缺配置时的错误提示
4. 优化前端页面中的缺配置引导
5. 补充配置说明文档

**交付物**

- 配置项清单
- 优化后的错误提示

**验收标准**

- 缺配置时无模糊错误
- 用户知道去设置页或环境变量处修复

---

### T5-07 API 集成测试补齐

**目标**

- 降低回归风险，验证关键接口主流程

**覆盖建议**

- `/api/categories`
- `/api/keywords`
- `/api/articles`
- `/api/wiki/ingest`
- `/api/wiki/index`
- `/api/wiki/lint`
- `/api/report/generate`
- `/api/content/generate`

**子任务**

1. 搭建 API 集成测试基线
2. 为关键接口补正常流测试
3. 为参数缺失补异常测试
4. 为空数据场景补边界测试

**交付物**

- API 集成测试文件
- 测试结果报告

**验收标准**

- 关键接口覆盖率达标
- 主链路关键节点有自动化回归保障

---

### T5-08 E2E 主链路测试补齐

**目标**

- 从用户视角验证系统核心流程

**覆盖建议**

1. 首页进入
2. 分类切换
3. 文章提取到 Wiki
4. Wiki 页面查看
5. 报告生成
6. AI 写文流式输出

**交付物**

- E2E 用例
- 回归执行结果

**验收标准**

- 核心流程可自动化验证
- 页面状态与用户操作一致

---

### T5-09 页面空态与异常态统一

**目标**

- 统一空态、缺配置、无结果、加载失败等页面反馈体验

**子任务**

1. 盘点各页面空态
2. 盘点各页面错误态
3. 统一文案、交互与视觉层级
4. 明确“去哪里修复”的引导路径

**交付物**

- 页面空态/异常态规范
- 对应前端实现

**验收标准**

- 空态和错误态不再零散
- 用户知道下一步该做什么

## 6. 完成定义

当以下条件全部满足时，第五轮迭代任务拆解可视为完成落地：

- 数据结构已对齐
- 文档契约已收口
- 核心主链路已跑通
- 错误结构已统一
- Pipeline 可恢复或可追踪
- 关键 API 有集成测试
- 关键页面有 E2E 测试
- 已知风险已明确记录

---

## 7. 一句话总结

第五轮迭代的任务拆解重点，不是继续加模块，而是把现有功能真正整理成一套可联调、可回归、可验收、可稳定运行的版本。
